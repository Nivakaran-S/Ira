# Milestone 3: Offline mode, design notes

**Date:** 2026-11-07. Implements platform spec §4.4 and §7.

## Decisions

| Topic | Decision |
|---|---|
| App shell | Angular service worker (production builds) caches the till's code; all lazy routes preload so an offline till can reach every screen. API responses are never cached by the worker. |
| Local store | Raw IndexedDB (`pos-local`), every value sealed with AES-GCM under a non-extractable key generated at enrolment (`DeviceRecord.dataKey`). Dexie was not needed: with encrypted values its query features do not apply. Wiped when the server reports the device revoked. |
| Down-sync | `GET /api/pos/sync/down?cursor=N`: categories, products and tax groups with `version > N` from one global `sync_version` sequence (triggers bump it on update; a tax-rate or membership change bumps its groups). Staff with a PIN and their permissions are sent in full each time; PIN hashes never are. |
| Offline PIN sign-in | When someone signs in online on a till, the till stores a PBKDF2-SHA256 (210k iterations, random salt) verifier of the PIN they typed. Offline, only those people can sign in, with the same 5-tries/15-minute lockout. Manager approvals offline use the same verifiers. |
| Outbox | Sales, refunds and cash movements made offline. Each op has `seq`, `prevHash`, `hash = sha256(prevHash + canonical{seq, kind, createdAt, payload})` and an ECDSA signature over the hash by the device key. |
| Up-sync | `POST /api/pos/sync/up`, device-signed (no user session needed). Per op: duplicate ids are acknowledged; ops that are not provably from the device are quarantined and do not move the chain; a gap is quarantined but the chain continues from it (the signature proves the device made it). |
| Verification | Offline window measured from the device's last contact before the batch (`settings.offline.maxHours`); no future timestamps; prices and taxes compared with the catalog when nothing about the product changed after the till's `catalogVersion`; totals re-computed with the till's own snapshot; payment methods (`offline.allowCard`); approvals re-checked against current permissions; refunds up to `offline.maxRefund`. |
| Quarantine | `SyncQuarantine`, reviewed in the back office (`sync.review`). Accept applies the op with window, approval, price and method checks waived; arithmetic is never waived. Bad signatures can only be rejected. Both are audited. |
| Receipt numbers | Offline receipts are `{register}-O{n}` from 200-number blocks reserved per device from `Register.offlineSeq`; online numbering stays contiguous. |
| Scope offline | Selling (cash; card if allowed), discounts and price overrides with local manager approval, pay-in/out and no-sale. Opening and closing shifts, voids and refunds need the connection (refunds need sale line ids that only exist once a sale has synced). Closing a shift is blocked while the outbox is not empty. |
| Hard stop | The till refuses offline sales once `maxHours` have passed since the last successful sync, and shows why. |

## Known limits

- The down-sync cursor is the highest version returned. A catalog write that commits after a later-numbered one could be skipped until its row changes again; catalog writes are short single-row transactions, so this is accepted.
- The till's initial bundle includes zod via `@pos/shared` (about 250 kB); the budget was raised to 900 kB.
